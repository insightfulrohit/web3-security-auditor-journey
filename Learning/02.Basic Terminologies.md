# Basic Blockchain Terminology --- One-Line Definitions

## 1. Blockchain Core Concepts

-   **Blockchain:** A digital chain of blocks that stores records
    securely.
-   **Distributed Ledger:** A shared record of transactions kept by many
    computers.
-   **Node:** A computer that connects to and participates in a
    blockchain network.
-   **Peer-to-Peer Network (P2P):** A network where computers
    communicate directly with each other.
-   **Block:** A group of transactions stored together on a blockchain.
-   **Genesis Block:** The first block of a blockchain.
-   **Block Height:** The position or number of a block in the
    blockchain.
-   **Hash:** A unique fixed-length value created from data.
-   **Nonce:** A number changed during mining to find a valid block
    hash.
-   **Merkle Tree:** A tree structure used to efficiently verify
    transactions in a block.
-   **Merkle Root:** A single hash that represents all transactions in a
    block.
-   **Fork:** A change or split in the blockchain's rules or chain.
-   **Consensus:** The process nodes use to agree on the valid state of
    the blockchain.
-   **Gas:** The fee paid to perform an operation on a blockchain like
    Ethereum.
-   **Transaction:** An instruction that changes data or moves assets on
    a blockchain.
-   **Mempool:** A waiting area for transactions that have not yet been
    added to a block.
-   **Layer 1:** The main blockchain network where transactions are
    directly processed.
-   **Layer 2:** A system built on top of Layer 1 to make transactions
    faster or cheaper.

## 2. Consensus Mechanisms

-   **Proof of Work (PoW):** A consensus method where miners solve
    computational puzzles to add blocks.
-   **Proof of Stake (PoS):** A consensus method where validators use
    staked assets to help secure the network.
-   **Validator:** A participant that checks transactions and helps add
    new blocks in a PoS network.
-   **Mining:** The process of using computing power to create and
    secure blocks in PoW networks.
-   **Staking:** Locking or depositing cryptocurrency to help secure a
    PoS blockchain and earn rewards.

## 3. Cryptography Basics

-   **Public Key:** A cryptographic key that can be shared with others
    to receive or verify information.
-   **Private Key:** A secret key used to control blockchain assets and
    sign transactions.
-   **Address:** A blockchain identifier used to send or receive digital
    assets.
-   **Digital Signature:** A cryptographic proof that a transaction was
    authorized by the owner of a private key.
-   **ECDSA:** A cryptographic algorithm commonly used to create and
    verify blockchain digital signatures.
-   **Keccak256:** A cryptographic hash function that produces a 256-bit
    hash and is widely used in Ethereum.
-   **SHA-256:** A cryptographic hash function that produces a 256-bit
    hash and is used by Bitcoin.

## 4. Ethereum & EVM Basics

-   **EVM:** The Ethereum Virtual Machine is the system that executes
    Ethereum smart contract code.
-   **EOA:** An externally owned account controlled by a private key.
-   **Contract Account:** An Ethereum account controlled by smart
    contract code.
-   **ABI:** A format that tells applications how to interact with a
    smart contract.
-   **Opcode:** A low-level instruction that the EVM can execute.
-   **Storage:** Permanent smart contract data stored on the blockchain.
-   **Memory:** Temporary data space used while a smart contract is
    running.
-   **Calldata:** Read-only input data sent to a smart contract
    function.
-   **Stack:** A small temporary data area used by the EVM to perform
    operations.
-   **RPC:** A way for an application to communicate with a blockchain
    node.
-   **JSON-RPC:** A standard format used to send requests and receive
    responses from blockchain nodes.

## 5. Smart Contract Basics (Solidity)

-   **Solidity:** A programming language used to write smart contracts
    for Ethereum and EVM chains.
-   **Smart Contract:** A program stored on a blockchain that runs
    according to its code.
-   **Function:** A block of code that performs a specific task in a
    smart contract.
-   **View:** A Solidity function that reads blockchain data without
    changing it.
-   **Pure:** A Solidity function that does not read or change
    blockchain state.
-   **Payable:** A Solidity function or address that can receive native
    cryptocurrency.
-   **Modifier:** Reusable code used to add conditions or checks to
    functions.
-   **Constructor:** A special function that runs once when a smart
    contract is deployed.
-   **Fallback:** A special function called when a contract receives
    unknown function calls or certain data.
-   **Receive:** A special Solidity function used to receive native
    cryptocurrency without calldata.
-   **Interface:** A definition of functions that a contract can
    interact with.
-   **Library:** Reusable Solidity code that other contracts can use.
-   **Struct:** A custom data type that groups related values together.
-   **Enum:** A custom type that contains a fixed set of named choices.
-   **Mapping:** A key-value data structure used to store and find
    values.
-   **Array:** A collection of multiple values stored in order.

## 6. Tokens & Standards

-   **ERC20:** A standard for creating interchangeable tokens on
    Ethereum.
-   **ERC721:** A standard for creating unique tokens such as NFTs.
-   **ERC1155:** A token standard that can manage both fungible and
    non-fungible tokens.
-   **Mint:** The process of creating new tokens.
-   **Burn:** The process of permanently removing tokens from
    circulation.
-   **Transfer:** The process of moving tokens from one address to
    another.
-   **Approve:** Giving another address permission to spend a specific
    amount of your tokens.
-   **Allowance:** The amount of tokens an approved address is allowed
    to spend.
-   **Stablecoin:** A cryptocurrency designed to keep a stable value,
    often linked to a fiat currency.
-   **Wrapped Token (WETH):** A token that represents another asset in a
    form that can work with smart contracts.

## 7. DeFi Basics

-   **AMM:** An automated system that allows token trading without a
    traditional order book.
-   **Liquidity Pool:** A pool of tokens supplied by users for trading
    or other DeFi activities.
-   **LP Tokens:** Tokens given to liquidity providers as proof of their
    share in a liquidity pool.
-   **Slippage:** The difference between the expected price and the
    actual price of a trade.
-   **Swap:** Exchanging one cryptocurrency or token for another.
-   **Router:** A smart contract that helps find and execute token swaps
    or routes.
-   **Oracle:** A service that brings real-world or external data into a
    blockchain.
-   **Collateral:** Assets locked as security for a loan.
-   **Borrow:** Taking assets from a DeFi protocol with an obligation to
    repay them.
-   **Liquidation:** The forced sale or closing of a position when
    required conditions are no longer met.
-   **Flash Loan:** A loan that must be borrowed and repaid within the
    same blockchain transaction.

## 8. Security Basics

-   **Reentrancy:** An attack where a contract is called again before
    the previous call has finished.
-   **Overflow/Underflow:** An arithmetic error where a number goes
    above or below its allowed range.
-   **Front-running:** Acting on a transaction before it is confirmed to
    gain an advantage from its known details.
-   **MEV:** Extra value that can be gained by controlling the order or
    inclusion of transactions.
-   **DoS:** An attack that prevents a system or contract from working
    normally.
-   **Phishing:** Tricking users into revealing secrets or approving
    harmful actions.
-   **Rugpull:** A scam where project owners take users' funds and
    abandon the project.
-   **51% Attack:** An attack where one entity controls most of a
    blockchain's mining or validation power.
-   **Sybil Attack:** An attack where one attacker creates many fake
    identities or nodes.
-   **Replay Attack:** Reusing a valid transaction or signature in an
    unintended place or situation.

## 9. Web3 Infrastructure Basics

-   **Wallet:** A tool used to manage blockchain accounts, keys, and
    transactions.
-   **Seed Phrase:** A set of words used to recover a blockchain wallet.
-   **Private Key:** A secret value used to control an account and sign
    transactions.
-   **Cold Wallet:** A wallet kept offline to reduce exposure to online
    attacks.
-   **Hot Wallet:** A wallet connected to the internet for easier access
    and transactions.
-   **MetaMask:** A popular wallet used to interact with Ethereum and
    other EVM networks.
-   **IPFS:** A distributed system for storing and sharing files using
    content-based addressing.
-   **ENS:** A naming system that maps human-readable names to
    blockchain addresses and other data.
-   **Block Explorer:** A website or tool used to view blocks,
    transactions, addresses, and other blockchain data.

## 10. Bitcoin Basics

-   **UTXO:** An unspent transaction output that represents bitcoin
    available to be spent.
-   **Mining Reward:** Bitcoin given to miners for successfully adding a
    new block.
-   **Halving:** An event that cuts the Bitcoin block reward roughly in
    half.
-   **Difficulty Adjustment:** A mechanism that changes Bitcoin mining
    difficulty to keep block production near its target time.
-   **Lightning Network:** A Layer 2 network designed to enable faster
    and cheaper Bitcoin payments.

## 11. Layer 2 Basics

-   **Rollup:** A Layer 2 system that processes transactions off-chain
    and posts data or proofs to Layer 1.
-   **Optimistic Rollup:** A rollup that assumes transactions are valid
    unless someone successfully challenges them.
-   **ZK Rollup:** A rollup that uses zero-knowledge proofs to prove
    that transactions were processed correctly.
-   **Sequencer:** A system that orders Layer 2 transactions and
    prepares them for submission to Layer 1.

## 12. General Web3 Terms

-   **Tokenomics:** The study of a token's supply, distribution,
    utility, and economic design.
-   **Trustless:** A system where users can rely on code and rules
    instead of trusting a central person or organization.
-   **Airdrop:** The distribution of free tokens to selected or eligible
    users.
-   **Vesting:** A system that releases tokens gradually over a set
    period.
-   **Whitelist / Allowlist:** A list of approved addresses that are
    allowed to perform a specific action.
